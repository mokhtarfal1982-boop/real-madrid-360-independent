# ريال مدريد 360 — النسخة المستقلة (المرحلة الأولى)

هذه نسخة مستقلة مشتقة من الكود الذي شاركه صاحب المشروع. **لم تُنشر على الإنترنت بعد.**

## ما تم تنفيذه
- الحفاظ على الواجهة والتفاعلات الأصلية.
- فصل الموقع الجديد عن عنوان بيانات Vercel السابق؛ أصبح يقرأ ملفات `/feed/` من الاستضافة نفسها.
- تضمين لقطة البيانات المرفقة داخل المشروع، مع الإبقاء على أدوات التحقق الموجودة. **هذه اللقطة تاريخية وغير متحقق من دقتها لحظة التشغيل**؛ لا يجوز وصفها بأنها تحديثات حية مؤكدة.
- إعداد نشر مستقل باستخدام GitHub Pages عند الدفع إلى فرع `main` أو التشغيل اليدوي.
- لم يحدث أي تعديل في مشروع Claude الأصلي أو حساب Vercel.

## التشغيل
`npm install` ثم `npm run build` ثم `npm run preview`.

## النشر
1. أنشئ مستودع GitHub جديدًا (ويُفضّل عامًا إذا كنت ستستخدم GitHub Pages المجاني).
2. ارفع ملفات هذا المجلد إلى جذر المستودع.
3. فعّل Pages واختر **GitHub Actions** مصدرًا للنشر.
4. ادفع التغييرات إلى فرع `main`، وستبني المهمة الموقع وتنشره.

## قبل النشر العام
- راجع الأخبار والنتائج والإصابات الموجودة في `site/feed/`، وكذلك البيانات الاحتياطية في `build/compile_data.py`، واحذف ما لا يمكن توثيقه.
- تأكد من مصادر حقوق الصور والبيانات.
- استبدل البيانات التاريخية بأخبار مثبتة بمصادر أصلية.
- اضبط العنوان الرسمي للموقع وبيانات المشاركة بعد الحصول على نطاق GitHub Pages.
- راجع المسارات المطلقة `/...` إن اخترت رابط مشروع GitHub Pages الفرعي؛ يفضّل نطاق مخصص أو نشر من الجذر.

## التحديث كل ساعة
هذا الإصدار **لا يدعي** وجود تحديثات آلية مؤكدة. مهمة GitHub Actions هنا تنشر الملفات التي تم تحديثها بالفعل فقط. التحديث الآلي كل ساعة يتطلب ربط مصادر بيانات مرخّصة/موثوقة، وبرنامج تحقق من الأحداث، وآلية لإيقاف نشر البيانات غير المؤكدة، ثم مهمة مجدولة. يمكن لمهمة ChatGPT أن ترسل متابعة تحريرية، لكنها لا تضمن النشر إلى الموقع.

## بنية النظام
- `src/` الواجهة والتفاعلات
- `site/` الملفات الثابتة ومصدر البيانات المحلي
- `site/feed/` الأخبار والمباريات والجداول والغيابات (لقطة أولية)
- `build/` أدوات البناء والتدقيق
- `.github/workflows/publish.yml` مهمة نشر GitHub Pages
